## Why Local AI for Kubernetes Operations?

`kubectl-ai` is an open-source Kubernetes CLI assistant that translates natural-language engineering intent into accurate Kubernetes manifests and `kubectl` diagnostic operations. By pairing `kubectl-ai` with a **self-hosted Ollama server**, platform engineers gain an AI copilot while keeping cluster topologies, namespace structures, and logs 100% inside their local or enterprise network perimeter.

## Architecture & Workflow

1. **Intent Parsing**: You invoke `kubectl ai` from your terminal with a operational prompt (for example, debugging a failing service or scaffolding a NetworkPolicy).
2. **Context-Aware Synthesis**: `kubectl-ai` inspects the relevant Kubernetes API schema and queries your local **Ollama** model (`qwen2.5-coder` or `llama3`).
3. **Human-in-the-Loop Confirmation**: Before any mutating command runs against the cluster, `kubectl-ai` presents the generated plan or YAML diff and waits for explicit engineer confirmation.

## Step-by-Step Implementation

### 1. Start the Local Ollama Model Server

```bash
# Install and start Ollama locally or on your GPU workstation
curl -fsSL https://ollama.com/install.sh | sh

# Pull a code-specialized open weights model
ollama pull qwen2.5-coder:7b
ollama list
```

### 2. Install `kubectl-ai` and Bind to Ollama

```bash
# Configure kubectl-ai to use the local Ollama provider
export OLLAMA_HOST="http://localhost:11434"

# Run an interactive diagnostic query against your current kubeconfig context
kubectl ai --llm-provider=ollama \
  --model=qwen2.5-coder:7b \
  "Find all pods not in Running state across all namespaces and explain why they are failing"
```

### 3. Generating Hardened Production Manifests

```bash
kubectl ai --llm-provider=ollama \
  --model=qwen2.5-coder:7b \
  "Create a production NGINX deployment in namespace web-prod with 3 replicas, non-root securityContext, readiness probe on port 8080, and CPU/memory limits"
```

## Production Takeaways

- **Never Bypass Confirmation**: Keep interactive approval enabled (`--require-confirmation`) when operating against staging or production contexts.
- **Pair with Least-Privilege RBAC**: Bind diagnostic AI sessions to read-only Kubernetes `ClusterRole` contexts (`view`) so exploratory troubleshooting cannot accidentally mutate cluster state.
