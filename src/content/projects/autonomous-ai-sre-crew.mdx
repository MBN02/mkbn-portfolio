## Engineering Challenge

Kubernetes clusters generate thousands of events, container logs, and metric time-series every minute. When a microservice enters `CrashLoopBackOff` or suffers an `OOMKilled` termination at 3:00 AM, on-call engineers must manually run `kubectl get events`, `kubectl logs --previous`, and inspect resource limits before deciding whether to restart the workload or escalate to the application squad.

## Solution Architecture

We built a complete **Local AI-Driven SRE Stack** spanning three open-source repositories (`autonomous-ai-sre-crew`, `local-ai-stack`, and `k8sgpt-cli-operator-setup`):

### 1. GPU-Accelerated Local LLM Infrastructure (`local-ai-stack`)

Using **MicroK8s / Kubernetes**, the **NVIDIA GPU Operator**, and **Ollama**, we provisioned an in-cluster inference service capable of running models like `llama3` and `qwen2.5-coder` locally with zero external network dependencies.

### 2. Multi-Agent SRE Crew (`autonomous-ai-sre-crew`)

Deployed as a Kubernetes `Deployment` bound to a least-privilege `ServiceAccount`, the Python **CrewAI** system coordinates specialized agents:

- **Telemetry & Event Watcher**: Detects failing pods and anomalous Golden Signals.
- **Forensic Diagnostician**: Fetches recent container logs and Kubernetes events, synthesizing a structured Root Cause Analysis (RCA).
- **Remediation Executor**: If the RCA identifies a transient deadlock or upstream timeout, executes a controlled rolling restart; if it detects a code defect or OOM limit breach, dispatches a rich diagnostic report with the exact YAML fix.
