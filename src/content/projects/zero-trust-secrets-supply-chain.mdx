## Engineering Problem

Modern platform security requires defending both the **delivery supply chain** (what code and container images are allowed into the cluster) and the **runtime control plane** (how workloads authenticate to downstream databases and APIs without leaking credentials in Git).

## Architectural Implementation

### 1. Dynamic Secrets Delivery with HashiCorp Vault & ESO

To reconcile GitOps (where everything lives in Git) with Zero Trust (where no secrets live in Git), we implemented **HashiCorp Vault** paired with the **External Secrets Operator (ESO)**:

```yaml
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: payment-service-db-credentials
  namespace: prod-payments
spec:
  refreshInterval: 1h
  secretStoreRef:
    name: vault-enterprise-backend
    kind: ClusterSecretStore
  target:
    name: payment-db-secret
    creationPolicy: Owner
  data:
    - secretKey: DB_PASSWORD
      remoteRef:
        key: kv/prod/payments/database
        property: password
```

Workloads authenticate to Vault using their short-lived Kubernetes `ServiceAccount` token, and ESO reconciles the runtime secret with automatic rotation.

### 2. Software Supply Chain Integrity (Harbor + Trivy/Snyk + Cosign + OPA)

1. **Vulnerability Scanning**: Every container image built in CI is scanned for OS and library CVEs using **Snyk** and **Trivy** and stored in a self-hosted **Harbor** OCI registry.
2. **Cryptographic Signing**: Validated images are signed using **Sigstore Cosign**.
3. **Admission Gatekeeping**: **OPA Policy Agent** verifies image signatures, prohibits mutable tags (`:latest`), and enforces resource requests/limits before the Kubernetes API server admits any pod.
