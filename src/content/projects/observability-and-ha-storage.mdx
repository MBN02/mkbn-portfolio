## Engineering Challenge

Running stateful workloads and high-traffic SaaS microservices on Kubernetes introduces two recurring failure modes:

1. **Observability Silos**: Metrics live in one tool while container logs require SSHing or running `kubectl logs` across dozens of pods during an outage.
2. **Stateful Persistence on Bare-Metal/Hybrid Nodes**: Local hostPath volumes tie pods to a single node, causing immediate downtime if a worker host fails.

## Solution Architecture

### 1. Metric-to-Log Correlation with Prometheus, Grafana & Loki (`monitoring-stack-kuberntes`)

We deployed the unified **kube-prometheus-stack** alongside **Grafana Loki**:

- **Metrics**: Prometheus scrapes `kube-state-metrics`, `node-exporter`, cAdvisor, CNI, and storage CSI metrics.
- **Logs**: Promtail DaemonSets tail `/var/log/pods/*`, attaching identical Kubernetes labels (`namespace`, `pod`, `app`) so engineers can pivot from a Prometheus latency spike directly to the exact pod log lines in Grafana.

### 2. Resilient Distributed Storage with Ceph & Longhorn

- **External Ceph via Ansible (`ceph-ansible`)**: Automated deployment of Ceph Monitor (`mon`), Manager (`mgr`), and Object Storage Daemon (`osd`) nodes providing self-healing RBD block volumes and CephFS shared file systems.
- **Longhorn Cloud-Native Storage (`longhorn`)**: Deployed via Helm with 3x synchronous volume replication across worker nodes and automated snapshot backups.
