## Engineering Challenge & Operational Context

Operating Red Hat OpenShift in an enterprise on-premises environment demands far more than standing up a cluster. When dozens of application teams rely on shared production and non-production clusters for business-critical services, platform engineering must solve three interlocking challenges:

1. **Zero-Downtime Lifecycle Management**: Upgrading control-plane operators, Red Hat Enterprise Linux CoreOS (RHCOS) kernel versions, and worker nodes without disrupting live production traffic or getting stuck in MachineConfigPool drain deadlocks.
2. **Workload Modernization Without Silos**: Supporting traditional virtual machine workloads alongside cloud-native microservices without forcing teams to manage two completely separate infrastructure stacks.
3. **Multi-Tenant Security & Disaster Recovery**: Guaranteeing strict tenant isolation (compute quotas, network micro-segmentation, non-root execution) and rapid, verified recovery of stateful data.

## Architectural Implementation

### 1. Defensive HA Upgrade Engineering (The 6-Gate Pattern)

To eliminate upgrade-induced incidents, I engineered a defensive upgrade protocol around OpenShift's **Cluster Version Operator (CVO)** and **MachineConfigDaemon (MCD)**:

```bash
# 1. Pre-Check Gate: Verify ClusterOperators, etcd quorum, and PDB health
oc get clusterversion,clusteroperators
oc get pdb -A | awk '$4 == 0 {print $0}'

# 2. Pause Worker MachineConfigPool to decouple control-plane and worker reboots
oc patch mcp worker --type merge -p '{"spec":{"paused":true}}'

# 3. Trigger Control Plane Upgrade and monitor rolling API/etcd convergence
oc adm upgrade --to=<target_version>
```

By pausing the `worker` MachineConfigPool during control-plane upgrades and unpausing workers in controlled batches with a **10-minute Prometheus/Loki soak window**, we prevent simultaneous node drains from overwhelming application replica counts.

### 2. Converged Container & Virtual Machine Architecture

Using **OpenShift Virtualization (KubeVirt)**, virtual machines are managed as native Kubernetes custom resources (`VirtualMachine` and `VirtualMachineInstance`) scheduled alongside standard Pods. Both workload types share:

- Declarative lifecycle management through **OpenShift GitOps (Argo CD)**.
- Unified observability pipelines via **Prometheus, Grafana, and Loki**.
- Policy-driven snapshot and disaster recovery protection via **Veeam Kasten K10**.

### 3. Enterprise Guardrails, Wiz CNAPP & Day-2 Automation

- **Identity & Access**: Replaced static cluster-admin credentials with corporate SSO identity providers and automated RBAC group bindings.
- **Posture Management**: Integrated **Wiz CNAPP** across clusters to continuously detect configuration drift, CVE exposure, and compliance gaps.
- **Self-Service Standards**: Published golden-path Helm/Kustomize templates enforcing startup, liveness, and readiness probes, `restricted-v2` Security Context Constraints, and explicit CPU/memory requests and limits.
