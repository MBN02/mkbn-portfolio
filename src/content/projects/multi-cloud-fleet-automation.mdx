## Engineering Challenge

Operating at enterprise scale—supporting **60+ Kubernetes clusters** and **200+ cloud projects** across GCP, Azure, AWS, and on-premises data centers—makes manual console provisioning impossible. Any inconsistency in network CIDR allocation, IAM bindings, container runtime configuration, or load balancer timeouts quickly compounds into production outages.

## Solution Architecture

### 1. Multi-Cloud Terraform Landing Zones

We built a versioned library of reusable **Terraform modules** covering:

- **Cloud Foundations**: Automated GCP Project Factory, Azure Landing Zones, hub-and-spoke VPCs, Cloud NAT, and least-privilege IAM bindings.
- **Managed Kubernetes**: Standardized GKE, AKS, and EKS cluster modules pre-wired with Workload Identity, private nodes, autoscaling node pools, and Prometheus telemetry.

### 2. Automated Bare-Metal HA Kubernetes & RKE2 (`rke2-ha-setup-ansible` & `kubernetes-ha-setup`)

For on-premises environments, we engineered zero-touch **Ansible playbooks** paired with **HAProxy + Keepalived**:

- **Layer-4 VIP Failover**: Two load-balancer nodes run Keepalived VRRP to maintain a floating Virtual IP (VIP) and HAProxy to distribute traffic across three control-plane nodes on port `6443`.
- **Idempotent Ansible Roles**: Automate swap disablement, kernel modules (`overlay`, `br_netfilter`), containerd/RKE2 server initialization, Calico/Canal CNI rollout, and worker registration.
