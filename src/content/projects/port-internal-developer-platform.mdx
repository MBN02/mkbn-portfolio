## Engineering Problem

In many enterprise organizations, adopting Kubernetes or OpenShift shifts the bottleneck from hardware provisioning to **platform ticket queues**. Application developers open tickets to request a namespace, wait for security teams to approve RBAC groups, wait again for firewall/NetworkPolicy rules, and manually copy YAML manifests between environments.

Our objective was to treat the **platform as a product** by building an **Internal Developer Platform (IDP)** using **Port** that gives developers immediate self-service autonomy while guaranteeing enterprise compliance by construction.

## Solution Architecture & Golden Paths

### 1. Software Catalog & Entity Modeling in Port

We modeled the enterprise platform topology inside Port across four core blueprints:

- **System / Application**: Business service metadata, owning squad, Git repository, and criticality tier.
- **Cluster & Environment**: Production and non-production OpenShift clusters (SNO staging, multi-node HA prod).
- **Tenant Namespace**: Mapped live from OpenShift with real-time CPU/memory quota utilization, active SCC profile, and Argo CD sync status.
- **Production Readiness Scorecard**: Automated rule evaluation tracking whether workloads define health probes, non-root security contexts, Vault ExternalSecrets, and Kasten backup labels.

### 2. GitOps-Backed Self-Service Workflows

When an engineer triggers **"Provision Application Environment"** or **"Request Quota Expansion"** in Port:

1. Port validates the payload against team ownership and tier policies.
2. A webhook triggers our automation pipeline, which scaffolds or updates a standardized **Kustomize overlay / Helm values** set in the GitOps repository.
3. **OpenShift GitOps (Argo CD)** reconciles the target cluster, provisioning the `Namespace`, `ResourceQuota`, `LimitRange`, `NetworkPolicy`, `RoleBinding`, and `SecretStore` atomically.
4. Status updates stream back to Port so the developer sees their live environment URL and health status within seconds.
